# NexChat — Product Requirements Document (PRD)

## 1. Executive Summary
NexChat is a high-performance, real-time messaging application inspired by Telegram, engineered for seamless cross-platform communication. It combines low-latency instant messaging with rich multimedia sharing, robust group/channel management, presence tracking, and privacy features. 

Designed with a modern aesthetic featuring clean glassmorphism, dynamic theme switches (Light/Dark mode), and fluid micro-interactions, NexChat provides an exceptional user experience on both desktop and mobile web environments, with an architecture ready for React Native mobile deployment.

---

## 2. Product Vision & Branding
* **Vision**: Deliver a secure, fast, and feature-complete real-time messaging experience that matches Telegram's gold standard user experience while establishing an original **NexChat** brand identity.
* **Branding & Design Language**:
  * **Original Identity**: Original NexChat logo mark, custom icon set, and unique color palette (Electric Telegram-Cyan `#2AABEE`, deep slate backgrounds, subtle glassmorphism). No proprietary assets or logos copied.
  * **Telegram Web UX Reference**: Left sidebar navigation, search, chat list with pinned chats, message bubbles with status ticks, date separators, sliding info panels, floating context menus, and inline media playback.
* **Target Audience**: Individuals, communities, content creators, and remote teams needing reliable real-time communication.
* **Core Value Propositions**:
  * Sub-100ms real-time message delivery.
  * Rich message features (voice, video, docs, reactions, editing, reply/forward, pinning).
  * Scalable broadcasts via Public and Private Channels.
  * Granular privacy controls (last seen, profile visibility, block lists).

## 4. Detailed Feature Specifications

### 4.1 Authentication & Profile Management
* **Registration / Login**: Email + Password with validation, Google OAuth 2.0 flow, and optional SMS OTP interface.
* **Token Management**: Dual JWT strategy (Short-lived Access Token in-memory/header, HttpOnly Secure Refresh Token cookie).
* **User Identifiers**: Unique searchable `@username` and system-assigned UUID.
* **Profile Customization**: Avatar upload (R2), full name, bio, and custom status message.

### 4.2 Real-Time Messaging & Chat Engine
* **Transport**: WebSockets via Socket.IO with automatic HTTP long-polling fallback.
* **Message Lifecycle**:
  1. Client emits `message:send` with client-generated temporary ID.
  2. Server persists message in PostgreSQL and broadcasts to recipient sockets.
  3. Server acknowledges back to sender with DB `id` and status `SENT`.
  4. Recipient device emits `message:delivered` and `message:read` events.
* **Message Editing & Deletion**:
  * Edit: Updates content in DB with `isEdited: true` flag and original timestamp preserved.
  * Delete: Hard delete or soft-delete ("Message was deleted") options per user preference.

### 4.3 Media & Attachment Engine
* **Direct Uploads**: Pre-signed URLs generated by NestJS backend for direct client uploads to Cloudflare R2 bucket.
* **Supported Media Types**:
  * Images (JPEG, PNG, WEBP, GIF) with client-side image compression.
  * Videos (MP4, WEBM) with thumbnail generation.
  * Audio (OGG/Opus, MP3) for voice notes.
  * Files/Docs (PDF, ZIP, DOCX, TXT) up to 100MB.

### 4.4 Groups and Channels
* **Groups**: Up to 200,000 members. Supported roles: Owner, Admin, Member.
  * Group permissions: send messages, change info, pin messages, add members.
* **Channels**: Unlimited subscribers. Admin-only publishing feed with optional comment threads.

## 5. Non-Functional Requirements

### 5.1 Performance & Latency
* **Message Latency**: $< 100\text{ ms}$ round-trip delivery under normal network conditions.
* **Page Load**: Next.js First Contentful Paint (FCP) $< 1.2\text{s}$, Time to Interactive (TTI) $< 2.0\text{s}$.
* **Concurrency**: Architecture designed to handle 50,000 active concurrent WebSocket connections via Redis Pub/Sub adapter.

### 5.2 Reliability & Availability
* **Availability Target**: 99.9% uptime.
* **Fault Tolerance**: Automatic WebSocket reconnection with offline message queuing (LocalForage / IndexedDB on client).

### 5.3 Scalability
* Stateless NestJS application servers scalable horizontally behind NGINX or AWS ALB.
* Redis caching for active user presence, rate limiting, and Socket.IO Pub/Sub message broker.

## 6. Key Performance Indicators (KPIs)
* **Real-time Delivery Rate**: $> 99.5\%$ of messages delivered within 200ms.
* **WebSocket Connection Stability**: $< 1\%$ unexpected disconnections/sec.
* **User Engagement**: Daily Active Users (DAU), Average Messages sent/user/day.
